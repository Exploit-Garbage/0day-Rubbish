# Maian Guardian 2.1 - OS Command Injection in the License Generator (`guardianLicense::create()`) (CWE-78)

Advisory: https://0day-rubbish.com/blog/maian-guardian-license-generator-command-injection
Repository: https://github.com/Exploit-Garbage/0day-Rubbish
Contact: disclosure@0day-rubbish.com

## Summary

Maian Guardian 2.1 is a self-hosted licensing system for PHP applications encoded with SourceGuardian, sold as a commercial script by Maian Script World (United Kingdom); it runs as roughly 308 plain PHP files against a MySQL database and exposes an administrator back-end under `/admin/`, a buyer portal and a remote license-issuing API. Its license-generation routine builds an operating-system command line by string interpolation and passes it to `shell_exec()` at `control/classes/class.licensing.php:261` inside `guardianLicense::create()`, in order to invoke the external SourceGuardian generator binary. Several of the interpolated fields arrive unvalidated from the body of the administrator AJAX operation `POST /admin/index.php?ajax-ops=generate` — `projid`, `projkey`, license property key/value pairs and the encoder string — and are placed inside double quotes rather than argument-quoted, so POSIX command substitution still applies: a `$(...)` in the project identifier executes during shell expansion, before the generator binary is ever resolved. The decisive detail is the sanitizer: the class ships a private method `escape()` whose entire body is `return $data;` (`class.licensing.php:68-70`), and it is the function called on the way to the shell, while `escapeArg()` — the correct `escapeshellarg()` wrapper, defined at `class.licensing.php:72-74` — has no call site anywhere in the product. We verified the chain end to end against a real installation: one authenticated request executed six injected commands, including a pipeline, and the proof marker read back over HTTP recorded `uid=33(www-data) gid=33(www-data) groups=33(www-data)` — the PHP/Apache service account, not root. The finding is authenticated and is published as such: the administrator gate held under eight bypass candidates, the remote API key is randomly generated at installation and was not bypassed, and the product ships no factory credential because the installer sets the administrator account.

- **Component**: administrator back-end, license generation — the `generate` operation of the AJAX switchboard `admin/control/system/_ajax.php:73-124`, reaching `guardianLicense::create()`
- **Sink and source**: sink is `shell_exec()` at `control/classes/class.licensing.php:261`; source is `$_POST['projid']` at `admin/control/system/_ajax.php:111`, assigned to the object member at `class.licensing.php:44` and concatenated raw into `--projid "<value>"` at `class.licensing.php:112`
- **Sanitization**: none that has any effect — `escape()` (`class.licensing.php:68-70`) and `mswCD()` (`class.licensing.php:152-154`) both `return $data;`, the global POST filter at `control/functions.php:342` applies `trim()` only, and the real escaper `escapeArg()` is dead code
- **Execution identity**: web server service account, observed as `uid=33(www-data)`; six further tainted fields and a second entry point (`control/api/api-remote.php:136-154`) reach the same sink

## Affected Products

- Maian Guardian 2.1, the self-hosted SourceGuardian licensing system, from Maian Script World (United Kingdom); commercial closed-source PHP distribution
- Affected component: license generation in the administrator back-end — `guardianLicense::create()` in `control/classes/class.licensing.php`, reached from the `generate` operation of `admin/control/system/_ajax.php`, and from `control/api/api-remote.php` for API key holders
- Runtime stack: PHP 8 with MySQL, plain PHP (no framework), approximately 308 PHP files; the tested instance ran on a stock PHP 8.3 Apache image with a MySQL 8 backend
- Only version 2.1 was installed and tested; no other version, edition or bundle is claimed, and the vendor's other products were not audited
- Verification method and boundary: static analysis of the shipped source plus one dynamic end-to-end run over HTTP (login, injection, proof read-back). Six further tainted fields on the same sink and the remote API entry point are established by source reading only, not by execution. The testbed used `/bin/echo` in place of the genuine SourceGuardian generator binary, which we did not possess; a run against a production installation carrying the real binary was not performed, although command substitution is evaluated before the command word is resolved so the placeholder cannot suppress the injection
- Testbed configuration that was ours rather than the product's: the loopback listener binding, the administrator password chosen for the engagement (set through the product's own install wizard), the placeholder generator path, and a document root writable by the service account
- Privilege ceiling: `uid=33(www-data)`, the PHP/Apache service account. Root was not reached and not attempted; no privilege escalation is claimed, and no unauthenticated variant exists

## Impact

- Arbitrary OS command execution as the web server service account from a single authenticated administrator POST, demonstrated with six distinct commands including a pipeline and output truncation
- Persistence: the service account wrote a file into the document root that the web server then served, which in a deployment that executes PHP from that tree is a durable implant surviving sessions and restarts
- Licensing data compromise: the same identity can reach the MySQL credentials in `control/_cfg.php`, so license records, project identifiers and keys, buyer identities and contact data, and the encoded-product inventory are readable and rewritable — an attacker can issue licenses for the customers' products and harvest the buyer list
- Session forgery: `guardian_access` is `SECRET_KEY` concatenated with a timestamp, and `SECRET_KEY` lives in `control/_cfg.php`; reading it yields administrator sessions with no password and no login event in the logs
- Second door: the remote API key in the `guard_settings` table opens `control/api/api-remote.php`, which reaches the same sink from outside the administrator back-end
- Stealth at the application layer: the `generate` request answered `HTTP 200` with its ordinary `{"status":"rdr"}` body, request bodies are not written to a default access log, and there is no error status or alert to correlate on
- Availability: the identity can corrupt or remove licensing data and application files, destroying the server's function for every encoded product that depends on it
- Ceiling: the host itself was not compromised and no escalation path was pursued; blast radius is what the service account owns on that machine

## Mitigation

1. Remove the shell from the path entirely (root cause): replace the `shell_exec()` call at `control/classes/class.licensing.php:261` with an argument-vector invocation such as `proc_open()` given an array, so the generator path is element zero and every option and value is its own element and no shell is spawned
2. If a shell invocation must remain, quote every interpolated value with `escapeshellarg()` including the license path currently wrapped in literal double quotes by `mswSGLicGenPath()` (`control/functions.php:123-125`); `class.licensing.php:112-113` must emit separate words rather than one interpolated string
3. Delete the no-op `escape()` (`class.licensing.php:68-70`) and the no-op `mswCD()` (`class.licensing.php:152-154`), and resolve the dead code either way: `escapeArg()` (`class.licensing.php:72-74`) wraps the correct primitive yet has no call site, which reads as a completed remediation that never landed
4. Validate the license-generation fields at the handler with a character allow-list and a length cap - alphanumeric is sufficient for SourceGuardian project identifiers, and the product already validates the staff `user` field this way at `admin/control/system/_ajax.php:432`; apply the same rule to project key, property keys and values, the encoder string, `hblock`, `timeservers` and `expire_in`
5. Validate the configured generator path before use: resolve it, require an existing executable regular file and require the expected basename, which also stops the settings field from pointing the shell at an arbitrary binary
6. Patch both entry points together: `control/api/api-remote.php:136-154` builds the same class from its own parameters, so a fix limited to the administrator AJAX operation leaves the sink reachable for API key holders
7. Introduce privilege separation around the generator: run it as a distinct unprivileged user, keep license output outside the document root, and make the web tree read-only for the service account
8. Harden the remote API key comparison as a separate change (`hash_equals()` on the raw configured key instead of unsalted MD5 digests compared with `==`), and ship a regression test asserting that a project identifier, project key or property value containing `$(`, a backtick, a double quote, `;`, `|` or `&` is rejected or passes through as literal text, with no child process spawned on rejection
9. Operator-side until a patch exists: restrict administrator credentials to trusted holders and treat them as shell access, expose the back-end only from a management network or an authenticated reverse proxy, make the document root read-only for the service account, enable file-integrity monitoring on the `content` tree, reject `generate` bodies containing `$(` or `%24%28` at the proxy, audit active `guardian_access` sessions against login events, and rotate `SECRET_KEY`, the API key, the administrator credential and the database credentials if compromise is suspected
