# LCDS Laquis SCADA — Unauthenticated `/uploade.html` File Write + Startup `CMDEXT*.DLL` Autoload = Pre-Auth RCE (CVSS 9.8)

## Summary
The web/HMI component of LCDS Laquis SCADA, `mili.exe` (PE32 Delphi console, 1129984 bytes, listening on `0.0.0.0:11234` per `var.ini [MODE] PORT=11234`, plus Modbus TCP on `0.0.0.0:502`), routes roughly twenty HTTP management endpoints through a single dispatcher, `fcn.0043c550`. That dispatcher does contain a password gate (`0x43ccf4`: `cmp dword [0x517bc0], 0` → `je 0x43cda0`), but the password is loaded from `var.ini [MODE] PASSWD` and the shipped configuration file contains no such key — so the jump is taken and **every endpoint is served with no authentication check at all**. Two of the unauthenticated endpoints chain into remote code execution. `POST /uploade.html` (handler `0x43d329`) writes the request body to disk under a filename lifted verbatim out of the attacker's `Content-Disposition` header (extracted at `0x43cc8e` by searching for a `"` and skipping 11 characters) into the process working directory — the same `app\data\` folder that the product's plugin loader scans at startup for the glob `CMDEXT*.DLL` (`0x50999c`), passing every match to `LoadLibraryA` through an indirect `driverserver` callback (`call [0x5171c4]`). Loading a DLL runs its `DllMain`, so anything an attacker can write into that directory becomes code executing inside the SCADA process; the loader checks no signature, no hash and no allow-list, and it tolerates a NULL `GetProcAddress("ComandosDLLDireta")`, so the planted image needs no exports. The second endpoint, `GET /reset.html` (handler `0x43cff2`), sets the accept-loop stop flag `[0x517b50] = 0` and halts the process — an unauthenticated denial of service that is also what makes the operator, a supervisor service or the next reboot restart `mili` and trigger the load. Neither step uses a credential, and the DLL persists on disk, so the chain is a classic pre-auth "plant + reboot" RCE against an industrial control system product, with the reboot provoked by the attacker. It was verified end-to-end on the real product binary: a credential-free upload landed a byte-identical `CMDEXT001.DLL` (SHA-256 `a0ed51cbcfa4c55095fe604ebfb708754ef33b3723a9032a0ae24a2349ae37b0` both in memory and on target), a credential-free `/reset.html` killed PID 6748 and port 11234, and after the restart (PID 24624) the marker file written by the implanted `DllMain` appeared within one second with content `LAQUIS_UNAUTH_RCE_OK`. No matching public CVE was found; the known Laquis CVEs all concern LQS file parsing, not the web component.

- **Score**: 9.8 Critical

## Affected Products
- **Product**: LCDS Laquis SCADA (closed-source SCADA/HMI, ICS / critical infrastructure)
- **Component**: `mili.exe` web/HMI server (HTTP 11234, Modbus TCP 502)
- **Versions**: the release installed from the installer under test (`LAquisSetupenge1.exe`, 1237 files via `innoextract`). The exact marketed version/build is **not documented in our research record**, so no specific version is claimed; any deployment whose `mili.exe` carries the ungated `/uploade.html` handler and the `CMDEXT*.DLL` autoload plugin loader has the same defect
- **Vendor**: LCDS (Brazil)
- **Prerequisites**: no credentials. The Laquis web server feature must be active (the operator-enabled state used for remote HMI/web access), and `mili` must be restarted — a routine operational event that the attacker can provoke via unauthenticated `/reset.html`

## Impact
- **Confidentiality**: arbitrary native code inside the SCADA/HMI process can read tag databases, driver and protocol configuration, `config.xml` / `var.ini`, logs and reachable credential material
- **Integrity**: the attacker owns the process that writes tag values and commands field devices; unauthenticated tag-write endpoints (`/tagset.html`, `/tagsetmulti.html`) sit on the same dispatcher, and the disk-resident implant reloads at every start, persisting across restarts and reboots while operator displays keep reporting normal values
- **Availability**: unauthenticated `GET /reset.html` alone is a repeatable denial of service against the HMI/web server — loss of operator visibility and alarming during a process upset, independent of the RCE step
- **Lateral / safety**: the same process serves Modbus TCP 502 toward field devices, so this is a pivot into control-network territory (PLCs, gateways, engineering workstations); because tag values and commands mediate physical actuation, tampering can reach the physical process with attendant personnel and equipment safety risk
- **Detection resistance**: the implant is named `CMDEXT*.DLL` — the product's own legitimate plugin naming scheme — and is loaded by the product's own loader at a normal lifecycle point, producing no anomalous child process and no shell-spawn telemetry

## Mitigation
1. Fail closed in the dispatcher: remove the `[0x517bc0] == 0` short-circuit at `0x43ccf4`/`0x43ccfb` so an unconfigured password denies state-changing endpoints instead of exposing them; require first-run password setup and replace the `?PWD=` query-string comparison with a real session mechanism (digest/TLS auth or signed session token, with lockout)
2. Harden `/uploade.html`: reject filenames containing path separators or `..`, confine writes to the data directory, enforce an extension allow-list that never permits loadable images (`*.dll`, `*.exe`, `*.ocx`), validate content, and restrict the endpoint to authenticated engineering sessions
3. Harden the plugin loader: verify Authenticode signatures (or a vendor signature/hash allow-list) before `LoadLibraryA`, and move `CMDEXT*.DLL` discovery out of any directory the web component can write
4. Gate `/reset.html` behind authentication with rate limiting and audit logging — anonymous parties must not be able to terminate the SCADA web service
5. Separate trust zones: do not serve the HTTP management API on `0.0.0.0` from the same process that hosts Modbus TCP and device drivers; require TLS and run the web component under a low-privilege service account
6. Audit the remaining unauthenticated endpoints (`/save.html`, `/saveconfig.html`, `/delete1.html`, `/logdelete1.html`, `/setip.html`) against the same requirements
7. Operator hardening pending a fix: block/bind TCP 11234 to trusted interfaces only (never expose to untrusted networks or the internet), set `[MODE] PASSWD` in `var.ini`, disable the web server feature if remote HMI access is not required, baseline `<install-dir>\app\data\` for file integrity (treat any `CMDEXT*.DLL` you did not deploy as compromise), and alert on unauthenticated `POST /uploade.html`, `GET /reset.html` and unexplained `mili` restarts
