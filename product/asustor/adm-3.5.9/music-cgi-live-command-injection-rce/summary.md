# Asustor ADM 3.5.9 (AS602T) — Post-Authentication Command Injection in `music.cgi` `act=live` → Command Execution in the CGI Process

Advisory: https://0day-rubbish.com/blog/asustor-adm-music-cgi-live-command-injection
Repository: https://github.com/Exploit-Garbage/0day-Rubbish
Contact: disclosure@0day-rubbish.com

## Summary

ASUSTOR's AS602T is an x86-64 NAS appliance from the vendor's first-generation (G1) firmware line, running ADM (ASUSTOR Data Master) 3.5.9.RWM1. Its management portal is served on TCP 8001 (HTTPS) and TCP 8000 (HTTP) as a tree of CGI handlers under `/portal/apis/`; the `fileExplorer` group contains `music.cgi`, the media handler examined here. In its `act=live` branch the handler composes an `ffmpeg` transcode command with `snprintf` at `0x4029a9` using the format string stored at `0x4035f8` — `%s -i "%s" -v 0 -ss %.2f  -vn -f mp3 -b:a 128000 -ac 2 -` — which places the stored file path **inside a pair of shell double quotes**, and then executes the resulting string through `As_System` (call at `0x4029b6`; `libgeneral.so.0.0` `0x4509b`). `As_System` is `system()`, i.e. `/bin/sh -c`. The identity that the injected command would hold on a device was **not measured** in this research: the uid 0 result reported below comes from the replication harness executing as root on an analysis host, and root for the on-device CGI process is an inference (handlers of this class on network-attached storage appliances commonly run as root), not a measurement.

The quoted path is fully attacker-controlled. It enters through the `file` parameter of `act=add` (`O_CGI_AGENT::Get_Param` at `0x401cab`), is split only on the three delimiter characters `,` `:` `?` (string at `0x4036f7`) and is copied verbatim into the music-list entry field at offset `+0x84` (list stride `0x484`); `music.cgi` never imports the library's general escaping helper. Before execution, `As_System` calls `Try_Escaping_Characters_To_Avoid_Command_Injection` (`0x44f95`), whose blacklist at `0xb25da` is exactly two bytes — backtick and `$` (`60 24 00`). When neither character is present the helper returns `0x72`, the escape buffer stays `NULL` and the original string is passed to `system()` unmodified. A file name such as `x";id>marker;#.mp3` therefore closes the vendor's own quote, chains an arbitrary command with `;` and comments out the remainder of the format string with `#`, without touching either blacklisted byte.

Access requires a valid portal session: `O_CGI_AGENT::Revive_Session` (call sites `0x4017b0` / `0x4017ee`) is fail-closed and is evaluated before any `act` dispatch, so this is a post-authentication finding. No physical AS602T was used and no whole-system emulation of ADM was achieved. The chain rests on extraction and disassembly of the shipped image, an independent re-extraction of `music.cgi` and `libgeneral.so.0.0` from that image by a second analyst with a raw-disassembly re-check of the sink, the argument registers (`rcx` / `r8` / `xmm0`), the `+0x84` offset and the escaping blacklist (confirmed, confidence 0.93), an adversarial falsification pass that could not refute any link (0.92), and a faithful C replication of the `snprintf` + `As_System` + `Try_Escaping` chain executed as uid 0 on the analysis host — the only place in this research where uid 0 was measured — which produced a 39-byte root-owned marker containing `uid=0(root) gid=0(root) groups=0(root)` for the quote-breakout payload while a `$(...)` control payload and a benign file name produced nothing. A factory default administrator credential pair exists in this build (CWE-798) and is reported as a separate issue; it is not the vector used here and it does not affect the score below.

## CVSS Score

- **Score**: 8.8 High (CVSS version 3.1)
- **Vector**: AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H = 8.8
- `PR:L` because `Revive_Session` enforces a valid session and no role restriction was found inside `music.cgi`; a deployment that confines the media library to administrators is instead scored AV:N/AC:L/PR:H/UI:N/S:U/C:H/I:H/A:H = 7.2
- An unauthenticated variant is not claimed — a 9.8 figure would require `PR:N`, and the eleven pre-authentication portal interfaces reviewed contain no `As_System`/`As_Popen` sink

## Affected Products

- **Verified**: Asustor AS602T (x86-64, G1 firmware line) running ADM 3.5.9.RWM1 — full static analysis of the shipped `music.cgi`, `libgeneral.so.0.0` and `libapp.so.0.0`, plus the executed sink replication
- **Cross-checked at code and command level**: Asustor AS1002T (ARM Marvell 88F6820, armv7 hard-float) running ADM 4.0.7.RVG1 — `music.cgi` imports `As_System` and `Get_Param` but not `Get_Escaped_String_General`, the `-i "%%s"` sink format is byte-identical, and the constructed command produced a root marker under ARM user-mode emulation with the build's own root filesystem
- **Unverified candidates**: other ADM builds older than 5.1.2 — the pre-Deadbolt generation — on other models share the root-cause pattern in principle, but no per-model byte-level comparison was performed and they are not reported here as affected
- **Not affected on the evidence**: in the newer ADM 5.1.4 build compared during this research, `As_System` and `As_Popen` remain exported at the same offsets but have no callers, and command execution moved to `Execute_Command_File` / `Execute_Command_Line` (`fork` + `execv` + argument tokeniser, no shell)
- **Not tested dynamically**: no modern ADM release was run in this work, and nothing in this advisory implies that any current ADM version is vulnerable. The carve-out is about dynamic testing only — ADM 5.1.4's code **was** examined statically during this research and was found to have removed shell invocation (`As_System`/`As_Popen` exported but with no callers, execution moved to `Execute_Command_File`/`Execute_Command_Line`, i.e. `fork` + `execv` + an argument tokeniser)
- **Prerequisites**: a valid ADM portal user session (any authenticated user on the evidence available) and a writable share directory such as `/volume1/home/admin`

## Impact

- **Confidentiality (High)**: command execution in the CGI process's identity — uid 0 measured in the replication harness, inferred for the device and not measured there — on a storage appliance reads every volume, share and snapshot it hosts, including other users' home shares and any backup data landed on the device — an authenticated low-privileged user reaches data belonging to everyone else, because no privilege separation exists between the portal role and the file system
- **Integrity (High)**: arbitrary write access allows stored data to be modified or destroyed, firmware-update staging files to be replaced, persistent implants to be installed in the root filesystem or scheduled tasks, and device configuration and credential stores to be rewritten
- **Availability (High)**: the device can be stopped or rebooted, shares unmounted, or data encrypted or wiped — the outcome that made appliances of this class a target of the Deadbolt ransomware campaign in the first place
- **Pivot and exposure**: root on the NAS, if that is the identity the on-device CGI process holds, is a durable position inside the LAN segment the appliance serves, and where the portal is published to the internet for remote access, a single valid portal credential is the only barrier between an internet-based attacker and full control of the device

## Mitigation

1. Execute the transcoder without a shell: replace the `As_System` call at `0x4029b6` with `fork` + `execv` (or `posix_spawn`), passing `/usr/local/AppCentral/ffmpeg/bin/ffmpeg`, `-i`, the path and the remaining options as separate argv elements — the vendor already ships this primitive as `Execute_Command_Line` / `Execute_Command_File` in newer builds
2. Retire the shell wrappers library-wide: delete `As_System` (`0x4509b`) and `As_Popen` (`0x450f1`) from `libgeneral.so.0.0`, or leave them exported with no callers as the newer generation already does, which closes the class for every present and future call site including the unanalysed `download.cgi` and `share_link.cgi` siblings
3. Stop treating a two-byte blacklist as an injection defence: `Try_Escaping_Characters_To_Avoid_Command_Injection` inspects only backtick and `$`, so it cannot protect a string interpolated inside double quotes — prefer rejection over rewriting, and at minimum handle `"` `'` `;` `|` `&` `<` `>` `(` `)` and newline
4. Allow-list file names at both ends of the path: enforce `^[A-Za-z0-9._ -]+$` (or a server-generated safe name) at `upload.cgi` and at the `Get_Param("file")` ingest in `act=add`, and again immediately before the `snprintf` at `0x4029a9`; call the existing `Get_Escaped_String_General` helper at the command-construction site if a shell path is retained
5. Never build a command from a client-supplied name: store uploads under a server-generated identifier and keep the user's chosen name as display metadata only, so the field at `entry + 0x84` contains no attacker-controlled characters
6. Reduce the blast radius: run the media CGI handlers and their transcode children under a non-root service account instead of uid 0, and — as a distinct CWE-798 remediation — retire the factory default administrator credential pair and force a password change at first login
